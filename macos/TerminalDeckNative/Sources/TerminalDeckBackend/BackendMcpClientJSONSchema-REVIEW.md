## Findings sent to owners

1. `Compiler.Builder.add`: eagerly adding `additionalItems`' child when `items` is not tuple-form resolves refs that the source ignores. The [official additionalItems implementation](https://raw.githubusercontent.com/ajv-validator/ajv/v8.17.1/lib/vocabularies/applicator/additionalItems.ts) returns before compiling the subschema in that case. Test `testTupleAndHomogeneousItemsDraft07` includes an ignored unresolved ref. Also review inactive if/then/else: the official if implementation returns without evaluating its condition when neither clause contributes rules; standalone then/else should not compile otherwise unused children.
2. Type-error ordering requires [getSchemaTypes/coerceAndCheckDataType](https://raw.githubusercontent.com/ajv-validator/ajv/v8.20.0/lib/compile/validate/dataType.ts) and [schemaKeywords](https://raw.githubusercontent.com/ajv-validator/ajv/v8.20.0/lib/compile/validate/index.ts), rather than always putting type first. A single declared type with applicable type-group rules defers the type refusal to that group, after general const/ref/combinator work. `testSingleTypeDiagnosticCanFollowGeneralRulesWhenTypeGroupHasRules` pins both cases.
3. The same compiler source still enforces keyword schema value types even with meta validation disabled. It formats the allowed types as JSON arrays. Negative numeric limits are not forbidden by that disabled meta-schema. Existing explicit tests cover this difference. Unknown extension annotations are inert.
4. [Default multipleOf](https://raw.githubusercontent.com/ajv-validator/ajv/v8.20.0/lib/vocabularies/validation/multipleOf.ts) uses division and integer comparison without an epsilon when precision is unset. The test preserves the 0.3/0.1 rejection instead of silently making it mathematically tolerant.
5. Format helper source matched the official regex flags/calendar arithmetic/full table in static review. An owner comment/test initially described final newline acceptance for `$`. [ECMAScript CompileAssertion](https://tc39.es/ecma262/2022/multipage/text-processing.html#sec-assertion) permits the pre-line-terminator case only with multiline enabled. Owner corrected the comment/tests; the existing JSC execution helper already followed that rule. Byte's global/multiline valid-line behavior remains intentional.
6. Parent's new `BackendMcpClientJSONSchemaIntegration.swift` and 4 integration tests were read. The wrapper keeps raw compile diagnostics for preparation and supplies the SDK call-time error envelope for evaluation exceptions. No confirmed issue in that wrapper/factory. Existing pool's metadata gate rejects boolean child schemas before this validator runs; parent owns the exact integration relaxation and preparation hook, so this lane did not edit those files.

Core interpreter, helpers/compiler/ref graph and parent wrapper/tests have now been reviewed statically; none is runtime-verified. Core owner corrected deferred type ordering, exact string/key equality and inert additionalItems/standalone then/else compilation. Final new-source reread confirmed the additional findings addressed: if with only always-valid then/else skips the condition's unresolved refs; draft07 anyOf with an always-valid branch skips its whole branch compilation in Ajv when unevaluated tracking is off ([union source](https://raw.githubusercontent.com/ajv-validator/ajv/v8.20.0/lib/vocabularies/code.ts)); tests now pin these compile fast paths.
