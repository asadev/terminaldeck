# Start an agent

Before starting an agent, make a decision about the work. Starting another session is not the default response to every task.

1. Check the requested outcome, the existing agents' roles and their current jobs. Decide whether to do it yourself, continue the same job with an already working agent, or start one bounded job for another agent. Avoid duplicating work another session owns.
2. State the decision briefly: the agent, why its role fits, the exact scope and the expected result. Preserve the user's chosen AI, account, permissions and working folder. A new role or wider access requires the user's authorization.
3. Give the chosen named agent a self-contained brief: the task, relevant files or project, constraints, expected result and who receives it. Use the existing task/delegation tools or `sessions_conversations` to start a visible team chat. Keep follow-ups for that job in the same open conversation. Do not start a hidden second CLI.
4. Read the result, compare it with the brief and report it to the lead or Hoot. A reported result and a verified result are different; say which you have. Keep unrelated work out of the job.

Existing authorization covers ordinary delegation within that scope. Ask only when a missing choice, new access or wider work needs the user's decision; do not invent a new approval step.
