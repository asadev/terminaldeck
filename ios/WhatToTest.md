What to test — 0.7.0

Your last build was 0.6.0, and that one matters: every build before it still
asked for a six-digit copilot code and sent a message the desktop no longer
declares. If the copilot would not connect for you, that is why. There is
nothing to connect any more — pair the phone as *my device* and the copilot is
simply there; pair as a guest and it is not, deliberately.

THE COPILOT — IT NOW ANSWERS
Pair as my device. The Copilot tab should be present with nothing pressed, and a
run should start AND ANSWER. In 0.7.0 it started and never answered once: the
desktop typed your message into the agent's prompt without pressing Return, so
every message you ever sent is still sitting in a prompt somewhere. Send two or
three in a row, including a long one, and check each comes back. If a message
ever goes unanswered the box unlocks itself after half a minute rather than
staying dead.

Then revoke and pair again as a guest: no Copilot tab at all, Sessions and
Settings only. That absence is the feature, not a fault.

OPENING A SESSION
It should appear already at its latest output. No history scrolling past, no
part-way scroll positions, no glitch frames — on first open and on every return
to it. This is the same fault the desktop had and it had the same cause: the
terminal painting a backlog as it received it.

THE MACHINE SWITCH — THE CHIPS ARE NAMED NOW
With two machines paired, Sessions and Copilot both carry the switch at the top.
Check that picking the other machine actually moves you to its sessions rather
than relabelling the ones you were looking at.

The chips used to read 2JJGF8 and 9ZA6K3 — relay slot codes, which name nothing
you own. A machine paired from this build shows its own hostname; one paired
before it shows Mac or PC until you re-pair or rename it. Two machines can never
show the same chip.

WHAT WENT AWAY
"Resume where you were last time" is gone from the top of the session list.
Several paragraphs went with it. If a screen now says less than you expected,
that is the intent — a review of the desktop asked for the same thing
everywhere and the phone followed.

DROPPING A FILE ON A SESSION
On the desktop, drag a photo from Pictures or the desktop onto the chat box of a
session this phone started. It used to be refused with a paragraph about the
folder the session is held inside; it is now copied into that folder and
attached, with nothing said. The terminal view has always done this and the two
views disagreed.

WHAT IS NOT HERE YET, AND IS NOT A BUG
Four things, in the order they are coming: the chat view (a session on the phone
is a terminal and a key bar — the copilot has bubbles, an ordinary session does
not), the context bar, the usage ring, and per-session accounts. None of the
four travels on the wire yet. They are not missing from the phone so much as not
yet sent to it.
