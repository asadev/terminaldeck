1. Product

ApplicationTerminal Deck (iOS)

AuthoritySelf-classification as a mass market item under the Cryptography Note (Note 3 to Category 5, Part 2 of the Commerce Control List) and 15 CFR 740.17(b)(1).
Non-standard cryptographyNone. The product implements no proprietary or unpublished cryptographic algorithm. Every primitive it uses is a published international standard, listed in section 3.
CCATSNot applicable. A classification request is not required for mass market items using only standard cryptography.

3. Cryptographic functionality

The application establishes an authenticated, end-to-end encrypted channel between the user's phone and the user's own computer. Its purpose is confidentiality of the user's own terminal session as it crosses an untrusted relay; the relay carries ciphertext and holds no key.

Key agreementX25519 elliptic-curve Diffie–Hellman — RFC 7748, 128-bit security level (255-bit curve)
HandshakeNoise Protocol Framework, pattern IK (public specification, noiseprotocol.org)
EncryptionChaCha20-Poly1305 AEAD — RFC 8439, 256-bit key
Key derivationHKDF-SHA256 — RFC 5869, RFC 6234
HashSHA-256 — FIPS 180-4
Transport securityTLS as provided by the operating system
ImplementationApple CryptoKit (the operating system's own cryptographic library). No cryptographic algorithm is implemented from scratch by this product.

4. What the product does not do

  • It contains no proprietary, secret or non-standard cryptographic algorithm.
  • It provides no cryptographic functionality to other applications; there is no API, SDK, library or toolkit exposed to third parties.
  • It is not "cryptanalytic", does not perform key escrow or key recovery, and has no open cryptographic interface.
  • Its cryptography cannot be modified, extended or reconfigured by the user.
  • It is not designed or modified for government end-users, military use, or any specialised application.
