Download

Terminal Deck 0.1.0 for macOS 12 or newer — Apple Silicon, with an untested Intel build alongside it. Both are unsigned, which adds one step the first time you open it.

Releases on GitHub Build from source

Builds are published on the releases page. If nothing is listed there yet, build it from source — it is three commands and a few minutes.

Requirements

Exactly these. Nothing else is assumed about your machine.

macOS 12 or newer
Packaging produces an arm64 and an x64 disk image, but only the arm64 one has been run — the Intel build exists and is untested. Linux and Windows have no target configured at all.
An agent CLI
At least one of Claude Code, Codex CLI or Gemini CLI — installed and already signed in. Terminal Deck does not install them, and it never asks you for a login or an API key: the agent signs you in itself, in the terminal.
git
Only for the git panel. Everything else works without it.
The gh CLI
Only for the GitHub panel, which runs your own authenticated gh. brew install gh if you want it.
Node 22 or newer
Only to build from source. A downloaded build has no Node requirement.

On first launch the app checks what is actually on your machine and, if no agent is usable, shows you what it found rather than an empty window. Settings → Setup repeats that check at any time and prints the literal probe it ran, so a missing tool tells you the command as well as the conclusion.

Installing

  1. Download and unzip

    Take the macOS arm64 archive from the releases page and unzip it. Inside is Terminal Deck.app. It is an Electron app, so the unpacked bundle is around 300 MB.

  2. Move it to Applications

    Drag Terminal Deck.app into /Applications. Running it from ~/Downloads works, but Applications is where macOS expects it and where you will find it again.

  3. Open it the first time with right-click → Open

    Right-click (or Control-click) the app, choose Open, and then click Open again in the dialog that appears. After that first launch, double-clicking works normally and you never see the dialog again.

    Double-clicking it the first time will fail with a message about an unidentified developer, or about the app being damaged. Nothing is damaged — see below for why.

  4. If macOS refuses anyway

    Recent macOS versions sometimes will not offer the Open button at all. Open System Settings → Privacy & Security, scroll to the security section, and click Open Anyway next to the message naming Terminal Deck. That button appears only after you have tried to open the app once.

Why an unsigned build needs that step

Signing an app requires a paid Apple Developer identity, and notarising it requires uploading each build to Apple. This build has neither — identity: null is set in the packaging config, deliberately and visibly. macOS attaches a quarantine flag to anything downloaded from the internet, and Gatekeeper refuses to launch a quarantined app that is not signed and notarised.

Right-click → Open is Apple’s own override: it shows the same warning with an Open button, and accepting it records your decision for that specific app. It is not a workaround for a broken build; it is the documented way to say “I know where this came from”. If you would rather not take that on trust, build from source below — then the binary is one you produced on your own machine, and no quarantine flag is ever set.

Building from source

The repository is the whole product. Node 22 or newer, and about two minutes.

Run it in development

git clone https://github.com/asadev/terminaldeck.git
cd terminaldeck
npm install
npm run dev

npm run dev starts Electron with a hot-reloading interface. Main-process changes need a restart; interface changes do not.

Package a real .app

npm run pack:mac   # unpackaged .app, fastest to smoke-test
npm run dist:mac   # the disk images: dmg + zip, arm64 and x64

pack:mac leaves release/mac-arm64/Terminal Deck.app; dist:mac writes the .dmg and .zip for both architectures into release/. Both run npm run build first. Because you built it locally it carries no quarantine flag, so it opens on a double-click with no Gatekeeper step at all.

Build a release with the single dist:mac invocation rather than the two per-architecture scripts: electron-builder rewrites latest-mac.yml on every run and the last one wins, so building the arches separately leaves a feed file that lists only one of them. BUILDING.md in the repository has the detail.

Do not run npm run build while npm run dev is serving. They share the out/ directory, and the build overwrites what dev is running out from under it. Stop dev first.

Checks

npm test          # vitest
npm run typecheck # both tsconfigs

What this build does not do

Worth knowing before you install rather than after.

  • It does not update itself. There is no update feed attached to this build, and the About screen says so rather than pretending to check. New versions mean downloading or rebuilding.
  • It is not signed or notarised, which is the whole reason for the right-click step above.
  • Only the Apple Silicon build has been run. An Intel disk image is produced by the same command and has never been launched. Linux and Windows have no target configured.
  • Session sharing, translations and split panes are not built yet. The first two are absent entirely; split panes have layout code in the repository that nothing in the app renders, so the chords for it do nothing.
  • Cost, chat and session search read Claude Code transcripts. Codex and Gemini sessions run perfectly well; those three panels simply have nothing to read for them.
